## Как работает продолжение

Для альбома порядок — `event_date, created_at, id`; для семейных «Записей» — `created_at, event_date, id`. Направление прежнее. После последней строки возвращаются только строго следующие по этому полному порядку. Равные даты разрешаются timestamp и UUID. Граничная запись может исчезнуть — её сохранённых значений достаточно для продолжения.

Курсор включает версию, область фильтров, дату события, исходный timestamp и UUID; только в памяти приложения, без auth-токенов/паролей. Timestamp не переокругляется через JS Date и сохраняет микросекунды. До `.or()` проверяются UUID, календарная дата и ограниченный формат timestamp. Семья/ребёнок/период остаются отдельными обязательными фильтрами запроса; RLS продолжает отвечать за доступ. Raw-синтаксис сверён с [Supabase](https://supabase.com/docs/reference/javascript/or) и [PostgREST](https://docs.postgrest.org/en/stable/references/api/tables_views.html#logical-operators).
