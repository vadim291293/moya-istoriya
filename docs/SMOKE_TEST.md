## Сначала: независимые способы входа и сохранность капсул

SQL 001–011 уже применены, ничего вручную запускать не нужно. Добавлены две официальные native зависимости: остановить **свой** Metro и заново запустить из `C:\Users\user\moya-istoriya` командой `npx expo start -c`; открыть актуальную версию Expo Go/SDK 57, телефон и ПК в одной сети. Разработчик Metro пользователя не останавливал. Следующее — ручные проверки, пока не подтверждённые физическим устройством.

1. «Семья → Капсула времени». Ранее сохранённый раздел требует существующий пароль, не создания нового. Показать/скрыть пароль. После успешного входа сохранённые письма в списке.
2. «Настроить вход по биометрии» → существующий пароль **один раз** → «Включить биометрию» → OS подтверждение. Только если нет зарегистрированной биометрии ребёнка/постороннего: телефон принимает любого из зарегистрированных strong пользователей, не распознаёт родителя отдельно.
3. Закрыть раздел → увидеть две кнопки, без автоматического scan. «Войти по отпечатку» → палец → список, без ввода пароля. Отменить OS prompt → остаётся закрыто; можно повторить или выбрать «Ввести пароль».
4. «Ввести пароль» → ручной пароль → список **без** сканирования. Это не новый этап подключения. Снова закрыть → опять два способа.
5. Сохранить несекретное письмо, увидеть «Капсула сохранена на сервере». Вернуться домой, выйти из аккаунта, войти тем же email и открыть по прежнему паролю: то же письмо/вложения должны остаться. Для биометрии после logout нужно новое явное подключение — это не потеря письма. Если не видно, не создавать замену: проверить «Мои капсулы»/«Корзина», обновление/ошибку сети и прислать снимок.
6. Набрать несохранённое письмо → Back/«Вернуться к списку без сохранения»: предупреждение, «Остаться и сохранить» оставляет текст. Без нажатия «Сохранить капсулу» серверного письма нет. Не использовать секретный текст для испытания process death: RAM-черновик после logout/завершения может потеряться.
7. Нет сети при входе/обновлении → сообщение ошибки списка, не предложение первого письма. Подтверждённый save не становится «не сохранено» от ошибки последующего refresh. Не повторять неизвестную отправку новым письмом: использовать проверку той же операции.
8. Вызвать биометрию и свернуть/уйти из раздела/сменить аккаунт → поздний успех не показывает письмо. Фон закрывает открытый раздел; voice/video останавливаются. После изменения набора отпечатков нужен повторный opt-in по паролю. Неправильный пароль/временная блокировка/сеть не должны обходиться биометрией.
9. Родственник не видит кнопку и не получает доступ через прямую ссылку даже с паролем владельца. Восстановление пароля капсулы через подтверждение пароля аккаунта сохраняет старые письма/файлы и отключает устаревший локальный credential.
10. На iOS Expo Go только пароль; Face ID/защищённый credential проверить в отдельной сборке. Web — только пароль, без OS-биометрии. Если уже более 30 капсул, проверить следующую страницу и архив без дублей; реальные массовые данные специально ради теста не создавать.

Подробный отчёт: `CAPSULE_BIOMETRY_VERIFICATION.md`.

## Дополнительные сценарии первоначальных капсул под паролем

SQL 009/010/011 уже применены; ничего вручную в Supabase запускать не нужно. Учитывать новые зависимости и перезапуск выше. Эти проверки на реальном телефоне ещё не выполнялись разработчиком.

1. Войти создателем семьи → «Семья → Капсула времени». У родственника кнопки быть не должно; прямая ссылка не показывает форму/данные.
2. Придумать отдельный пароль минимум 8 символов, повторить его. Создать письмо, выбрать ребёнка, сохранить. Закрыть раздел, открыть: до пароля название/текст не видны. Одна неправильная попытка выдаёт ошибку, правильная открывает. Не блокировать собственный раздел пятью попытками без необходимости.
3. Прикрепить несекретные фото и короткое видео, сохранить; открыть, закрыть, повторно открыть после пароля. Фото увеличивается, видео использует обычный простой плеер; файлы не должны появиться в общей Фото/Видео-галерее. Выбор галереи может закрыть раздел — ввести пароль и продолжить возвращённый черновик.
4. По желанию записать голос, прослушать, сохранить; разрешение микрофона только по кнопке. Ни видео, ни голос не продолжают играть в фоне.
5. Отредактировать письмо. Дважды быстро нажать сохранение: одна капсула. При сетевой ошибке не создавать новую: «Проверить состояние на сервере»/повтор прежнего сохранения.
6. Написать несохранённый текст, свернуть приложение, вернуться: раздел закрыт, письмо не видно. После пароля черновик возвращается, пока процесс не завершён. Выход из раздела/завершение приложения может удалить черновик; сохранять важное заранее. Аналогично проверить автоматическое закрытие через 10 минут.
7. Перенести сохранённую капсулу в корзину с подтверждением; открыть закрытую корзину, вернуть. Текст/файлы сохранились. Это не безвозвратное удаление и не резервная копия.
8. «Забыли пароль капсулы?» — неправильный пароль аккаунта не сбрасывает защиту. Правильный пароль аккаунта + новый пароль раздела дают доступ к прежним письмам/файлам. Вход в основное приложение не должен измениться. Проверить второй семейный аккаунт: даже знание нового пароля не открывает капсулы.

Затем коротко проверить прежние Фото/Видео/Записи, добавление и просмотр, семью/корзину/выход — они не должны измениться. Подробный отчёт: `CAPSULE_VERIFICATION.md`.

## Короткий сценарий владельца на Android

1. В основной папке запустить `npx expo start -c`, открыть QR через Expo Go. Нормально: стартовый экран без `Intl.PluralRules`, `missing default export` и `ErrorBoundary` ошибок.
2. Зарегистрироваться своей почтой. Если Supabase требует подтверждение, открыть письмо на том же телефоне. Нормально: callback подтверждения, затем setup; не форма смены пароля после обычной регистрации. Если письмо не пришло, проверить Auth Logs/провайдера email, не отключать подтверждение всем пользователям ради обхода.
3. Создать семью и первого ребёнка. Нормально: главная показывает фактическую семью/ребёнка. При неизвестном результате не создавать семью вручную заново; перезапуск/проверка данных должны открыть уже созданную семью.

   Если действительно нужно добавить следующего ребёнка, на главной открыть вкладку «Семья», затем «Добавить ребёнка», ввести имя и явно выбрать дату рождения. Нормально: тот же family_id, появляется вторая карточка и отдельный альбом; предыдущие дети/воспоминания остаются. Дата не подставляется как сегодняшний день без выбора; будущая дата не принимается. Во время запроса поля/повтор/назад заблокированы. Этот шаг создаёт реальные данные: не выполнять его автоматически или с вымышленными данными без отдельного разрешения. При нескольких членствах после обновления может снова открыться выбор семьи.
4. На главной переключить «Вся семья» / ребёнка и обратно: галерея меняется на месте, нижняя панель остаётся. Выбрать год/календарный месяц, пустой месяц, затем «Все даты». В месяце только его события; pull-to-refresh/«Показать ещё» сохраняют диапазон. При быстрых переключениях поздний ответ старого месяца не подменяет текущий. Меню возрастных глав отсутствует. «Записи» показывает текстовые памяти. Старые записи без отметки ребёнка находятся в общем альбоме; новая форма с единственным ребёнком заранее отмечает его, «Вся семья» явно снимает отметку.

   В уже имеющейся семье с более чем десятью воспоминаниями пролистать несколько страниц и повторить во вкладке «Записи». Продолжение не должно дублировать/терять записи только из-за сдвига списка перед границей. Ошибка сети сохраняет просмотренное; повтор читает от той же границы. Refresh/смена ребёнка, месяца или вкладки сбрасывают продолжение. Курсор не даёт snapshot всего альбома: новые моменты перед уже пройденной границей появляются после обновления. Не удалять реальные воспоминания ради теста; сценарии удаления в локальном стенде синтетические.

   Для FlatList отдельно проверить длинный уже существующий альбом: быстрая прокрутка вниз/вверх, полный последний ряд из 1–3 файлов, месяцы только с видео и текстовые записи. Нет предупреждения о вложенных вертикальных VirtualizedLists, выпадений/перепутанных плиток или некликабельных кнопок. Проверить header, pull-to-refresh и «Показать ещё» в обоих режимах, включая альбом с текстом без медиа. На устройстве измерить FPS/память до/после нескольких страниц; результаты не считать уже известными из тестов. Для проверки выгрузки ячейки в development-сборке при просмотре фото/видео безопасно промотать лежащий под Modal список через диагностический стенд: просмотр остаётся открытым, плеер не дублируется. Не добавлять ради этого скрытую отладочную кнопку в production и не пытаться прокручивать список через закрывающую его модальную поверхность. Смена фильтра/аккаунта и фон закрывают просмотр. Android Back, pinch/свайпы и возврат из фона проверить физически.
5. Добавить одно несекретное оригинальное фото камеры с известной датой. Нормально: после выбора дата подставляется из EXIF; возраст/позиция в ленте соответствуют съёмке. Фото отображается в семейной ленте и книге без дублирования физического файла; оригинал не изменён подписью возраста. Нажать на сохранённое фото: открывается полный кадр, дата/возраст, закрытие крестиком и Android Back; несколько фото переключаются свайпом или миниатюрами, стрелок нет. Двойной тап и pinch увеличивают фото, его можно перемещать; при увеличении свайп не меняет фотографию. Проверить сброс масштаба, поворот экрана и выход в фон.
6. Добавить короткое тестовое видео меньше 50 МиБ. Нажать «Смотреть видео»: открывается отдельный полноэкранный просмотр с датой/возрастом, после готовности начинается воспроизведение. Нормально: нативные пауза/перемотка работают, ручная пауза не отменяется после буферизации. Крестик/Android Back/уход в фон закрывают просмотр и останавливают звук; после возврата он сам не открывается и не запускается. Закрыть видео и открыть фото той же смешанной записи: звук не остаётся за фотографией. Плеер не остаётся в карточке ленты и не включается для всех видео при открытии страницы. При недоступном файле видна ошибка с предложением закрыть и обновить ленту. Повторный вход в ленту обновляет доступ к файлу. Проверить портрет/альбомную ориентацию отдельно.
7. Нажать «Добавить» внизу главной (или «Добавить для ребёнка» в его альбоме), выбрать старое фото камеры. Отдельной конкурирующей кнопки старой памяти на главной нет. Нормально: доступная дата съёмки подставлена автоматически. Для фото без EXIF/видео требуется явная дата, не подставляется дата загрузки. Для разных дней отображаются даты файлов и пояснение; сохранить можно по одному дню либо явно указав общую дату. Ручную дату новый выбор фото не перезаписывает. Для события до рождения возраст не выдумывается. После сохранения архивная память находится в месяце события в галерее, а в общих «Записях» — как новое добавление. Снять фильтр месяца, если он не соответствует событию.
8. Закрыть и открыть приложение. Нормально: сохраняется вход, сразу открывается семья без повторного setup.
9. Выйти и нажать аппаратную кнопку «Назад». Нормально: приватные экраны не открываются. Войти той же почтой и точным паролем: открываются уже созданные семья/память, не новый setup. При `invalid_credentials` показать пароль, проверить раскладку/регистр/пробелы либо восстановить его самому; пароль агенту не отправлять. Затем проверить другой аккаунт: семья первого не появляется.
10. «Забыли пароль»: ввести свою почту, запросить и получить настоящее письмо, открыть последнюю ссылку на том же телефоне. «Запрос принят» в приложении не доказывает доставку: при отсутствии письма проверить «Спам», затем Auth Logs/SMTP проекта. Задать новый пароль дважды. Нормально: обычные экраны закрыты до завершения/отмены восстановления; двойное нажатие не отправляет два запроса. После подтверждённого обновления нажать «Войти с новым паролем»: локальная recovery-сессия завершена, открыт экран входа. Ввести ту же почту и новый пароль самостоятельно: открываются прежние семья/фото без setup. При потере ответа вместо успеха показано «Проверить вход»: попробовать новый пароль, при отказе запросить новую ссылку, не создавать новый аккаунт. Ошибка выхода оставляет кнопку для повторной попытки. Этот сценарий меняет реальный пароль и выполняется владельцем; пароль и полную ссылку агенту не отправлять.

   Старый/испорченный callback должен давать понятную ошибку, не вечную загрузку; повторная доставка уже обработанной ссылки внутри экрана не расходует её заново. Новая ссылка во время старого запроса не получает его поздний результат/старые поля. Старая кнопка не закрывает новую форму и не меняет пароль другого аккаунта. После отмены до сохранения пароль не меняется. Проверить возврат после закрытия/повторного открытия приложения отдельно.

Expo Go URL `exp://192.168.0.103:8081/--/auth/reset-password` привязан к сети/порту. Если адрес Metro изменился, нужны отдельная проверка и согласованное обновление allowlist. Callback установленной сборки: `moyaistoriya://auth/reset-password`.

## Android: восстановление прерванного выбора без серверной записи

Проводить отдельно на тестовом устройстве с заранее согласованным способом пересоздания Activity во время picker. Не менять настройки телефона/Windows автоматически. Эта проверка ещё не выполнена; unit-стенд не воспроизводит Android OS. До финального нажатия «Сохранить» шаги не отправляют файлы и не создают память в Supabase.

1. В существующем аккаунте/семье открыть «Добавить», заполнить текст, вручную выбрать дату и ребёнка. Открыть галерею и выбрать несекретное фото, когда Activity приложения пересоздаётся. После восстановления сессии открыть форму снова, если auth-shell вернул на главную. Нормально: поля временно заблокированы, затем прежний текст/ручная дата и файлы восстановлены, показано пояснение. Никакой автоматической отправки, ручная дата не заменена EXIF.
2. Повторить с автоматической датой и известным EXIF. Нормально: после восстановления показана дата съёмки, не дата загрузки. Если Android/видео/фото не вернуло дату, есть требование ручного выбора. Отмена/отсутствие native результата сохраняет прежние поля и объясняет необходимость выбора файлов снова.
3. До завершения результата уйти с формы/сменить доступное семейное пространство или войти другим уже существующим тестовым аккаунтом. Нормально: прежние поля/файлы не появляются в новой форме. Возврат к исходному аккаунту/семье позволяет восстановить результат, пока он не заменён новым явным выбором на устройстве.
4. Быстрые двойные нажатия выбора/сохранения не открывают вторую галерею и не отправляют память во время восстановления. После успеха видно не больше пяти файлов без дублей. Если local journal недоступен, форма показывает ошибку/повтор проверки и не заявляет об успешном сохранении. Не очищать данные приложения ради обхода ошибки.

Полное завершение процесса может потерять native slot. Журнал восстанавливает снимок перед галереей, а не все последующие изменения формы; гарантии восстановления при любом crash нет. Проверку с настоящей отправкой/потерей RPC выполнять только с отдельно согласованными тестовыми данными ниже.

## Проверки только с отдельно разрешёнными тестовыми данными

- Два независимых аккаунта/семьи: SELECT чужой семьи/ребёнка/памяти не возвращает строки; чужие вставки/связи/Storage-пути запрещены. Выполнять от пользовательской роли, не Dashboard postgres и не service_role.
- Два одновременных вызова setup одного пользователя: одна семья/первый ребёнок, повтор возвращает существующего ребёнка. До/после сравнить идентификаторы и количество записей; не тестировать на важных семейных данных.
- Прерывание сети во время RPC сохранения: после восстановления — «Проверить и повторить», та же память и те же файлы, без дубликата. Повторить после перезапуска. Не очищать локальные данные приложения при неизвестном результате.
- Добавление ребёнка при потерянном ответе INSERT: после возврата сети/перезапуска исходные имя/дата заблокированы, повтор проверяет тот же UUID. Нормально: одна новая строка children, прежняя семья, никаких вторых семей или upsert существующего ребёнка. Сменить аккаунт до ответа: его поздний результат не открывает/не обновляет данные нового аккаунта. Дополнительные тестовые дети в текущем запуске не создавались; реальная проверка этого сценария ещё не проведена.
- Ошибка одного файла/истечение подписанной ссылки: текст памяти и остальные файлы остаются доступны, жест вниз повторяет загрузку.
- Быстро переключать фото миниатюрами при медленном соединении: поздняя ошибка/загрузка предыдущего снимка не скрывает текущий и не меняет его spinner/масштаб. Свайп завершившегося старого кадра не перелистывает новую фотографию второй раз. После закрытия просмотр не возвращается от поздних событий.
- Отказ доступа к галерее, отмена picker, шесть файлов, файл больше 50 МиБ, плохой MIME: понятное сообщение, никаких ложных успешных записей.
- Двойной тап выбора открывает только одну галерею; до её ответа нельзя сохранить запись. Отмена не удаляет ранее выбранные файлы. При сохранении двух файлов последовательность «Подготавливаем файл 1 из 2», «Загружаем файл 1 из 2», затем второй файл, «Проверяем результат»/«Сохраняем запись» соответствует реальным этапам; процент не показывается. Повтор незавершённого RPC проверяет запись без повторной загрузки. Смена аккаунта при чтении/отправке не переносит фото/результат на другой аккаунт; отказ очистки сообщает о приватных временных файлах, не заявляет об их удалении.

Первые два пункта выполнены через живой API на тестовом наборе `fc9eaa50`: 51 проверка прошла, включая Storage и повторный вход. Остальные сетевые/нативные сценарии пока не выполнены на телефоне. Не создавать дополнительные тестовые данные и не удалять оставленный набор без нового точного разрешения.

## Ещё не реализовано

Фотография профиля ребёнка, передача владения/тонкие роли, постоянная резервная копия/экспорт, безвозвратное удаление и выпуск APK/магазины. Дополнительные дети, приглашения родственников, редактор и восстановимая корзина уже реализованы, но телефонный E2E ещё нужен. EXIF уже используется для доступной даты фото; дата видео/галереи без EXIF и автоматическое разделение большого импорта по дням ещё впереди. Zoom/свайп реализованы в коде и требуют проверки пальцами на телефоне. Полноценная iOS-проверка также впереди.
