# Восстановление выбора фото/видео на Android

Дата: 7 октября 2026. Исходники: `C:\Users\user\moya-istoriya`.

## Реализовано

- Перед открытием системной галереи Android записывается локальный маркер запроса, userId/familyId и снимок формы: заголовок, текст, дата с её ручным приоритетом, режим архивной записи, связи детей и ранее выбранные файлы.
- При следующем открытии `/memory/new` в той же семье/аккаунте форма проверяет маркер, временно блокирует поля/сохранение и получает результат через `ImagePicker.getPendingResultAsync`. После перезапуска auth-shell может сначала открыть главную: тогда нужно вновь нажать «Добавить». Автоматического перехода поверх входа/setup/выбора семьи нет.
- Результат SDK сначала записывается локально и затем передаётся форме. При blur, смене аккаунта или размонтировании поля не подставляются; результат остаётся исходному владельцу. Чужой userId/familyId не вызывает чтение глобального native pending slot.
- Глобальный слот соответствует устройству, не отдельной семье. Новый явный выбор заменяет прежнее намерение, как и native SDK. Это не хранилище нескольких черновиков. Физические файлы при замене/завершении маркера не удаляются.
- В журнал попадают только нужные локальные URI/тип/размер/имя/разрешение и валидный `DateTimeOriginal`. GPS, остальной EXIF, base64, web File и токены не записываются. Ручная дата сохраняет приоритет; при отсутствии/разных датах новых файлов без неё отправка запрещена. Связи детей сверяются с актуальной семьёй.
- Отмена/пустой результат/ошибка восстанавливают прежние поля без выдуманных файлов. Больше пяти результатов сопровождается предупреждением. Файлы объединяются без дублей, известные файлы больше 50 МиБ не добавляются.
- SDK-вызовы сериализованы. При сбое записи уже потреблённого native результата его компактная копия остаётся в RAM для повторной проверки в том же JS-процессе. Сбой чтения/подтверждения записи/удаления журнала не выдаётся за успех. Есть кнопка повторной проверки.
- Сохранение памяти остаётся только по нажатию пользователя. Очистка маркера происходит до загрузки/RPC, не после серверного commit. Незавершённый RPC-журнал имеет приоритет: старый picker draft не подменяет отправленный payload/UUID.
- На iOS/web Android-журнал и pending slot не используются; обычный выбор сохраняется, включая web File. Web запуск галереи достигается синхронно из пользовательского обработчика.

## Основание

Проверены [документация Expo ImagePicker SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/) и исходники установленного SDK: `node_modules/expo-image-picker/src/ImagePicker.ts`, `android/src/main/java/expo/modules/imagepicker/ImagePickerModule.kt`. Android может уничтожить Activity при выборе медиа. Native `getPendingResultAsync` очищает свой слот перед обработкой результата; поэтому одного вызова без app-owned маркера и сохранения результата недостаточно.

## Границы и ещё не подтверждённое

- Уничтожение Activity, реальные file/content URI после восстановления и доступность кэша нужно проверить на Android. Физического телефона в этом запуске не проверяли. Не менять настройки Android/Windows автоматически ради теста.
- Полное завершение процесса не всегда оставляет результат в native slot. Если SDK не вернул его, восстанавливаются прежние поля с предложением выбрать файлы снова. Если процесс умер между разрушительным native чтением и локальной записью, RAM-копия не поможет. Сохранность результата при любом crash не обещается.
- Снимок создаётся только перед галереей; после завершения выбора маркер снимается. Редактирование формы не является долговременным автосохранением черновика. Возможен узкий crash-интервал между подстановкой полей и снятием маркера.
- Журнал находится в существующем локальном хранилище без шифрования, содержит личный текст и локальные пути. Это не SecureStore; секреты туда не добавляются. Повреждённый журнал не стирается вслепую.
- Восстановление picker не устраняет отдельное ограничение: завершение приложения до RPC во время загрузки может оставить приватные непривязанные Storage-файлы. Автоматическая серверная очистка не внедрялась.
- Нативные zoom/свайп/видео, email callback и повторный вход владельца остаются отдельными телефонными проверками из `SMOKE_TEST.md`. Их нельзя считать выполненными по числу unit-тестов или JS-export.
