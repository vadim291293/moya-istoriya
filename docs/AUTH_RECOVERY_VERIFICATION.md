# Восстановление пароля — 8 октября 2026

Основная папка: `C:\Users\user\moya-istoriya`. Этот проход укрепляет существующие auth-shell, callback и экран входа; не меняет архитектуру, БД, RLS, Storage, SMTP или дизайн.

## Реализовано

- После подтверждённого `updateUser` для исходного пользователя: «Всё готово» → «Войти с новым паролем» → проверка текущей сессии → существующий локальный `signOut` → `/login`. Кнопка «Назад» делает то же самое. Восстановление не считается доказательством нового парольного входа.
- После потерянного/ошибочного/неполного ответа обновления: «Проверьте вход», поля очищены, «Проверить вход» завершает recovery-сессию перед новым входом. Нет автоматического повторного изменения пароля. Если новый пароль не подошёл, пользователь запрашивает новую ссылку.
- Известные отказы `weak_password`, `same_password`, ограничения частоты дают понятное сообщение и сохраняют редактируемую форму. Ошибка чтения сессии до обновления не называется сменой пароля.
- Обработчики формы, подтверждения, отмены и завершения привязаны к версии recovery-ссылки и этапу экрана; не работают после размонтирования. Новая ссылка/другой аккаунт отменяют действие старых обработчиков и применение поздних результатов.
- При выходе игнорируется только собственный ожидаемый `SIGNED_OUT`, а не вход другого пользователя. Перед выходом проверяется реальный session user ID. Ошибка выхода не открывает приложение и оставляет повторную попытку.
- Обычное подтверждение email регистрации не показывает парольную форму и сохраняет прежний переход «Продолжить».
- «Забыли пароль» отправляет нормализованную почту без необходимости вводить пароль и использует `Linking.createURL('auth/reset-password')`, не захардкоженный порт. Один запрос блокирует второй reset/вход; размонтированный экран не инициирует запрос.
- Сообщение «Запрос принят» не утверждает, что письмо уже доставлено, и не подтверждает существование указанного аккаунта. Пароли не сохраняются в локальный журнал/файлы и не выводятся в логи.
