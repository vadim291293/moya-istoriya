# Надёжность добавления фото и видео

Дата: 7 октября 2026. Исходники: `C:\Users\user\moya-istoriya`.

## Что изменено

- После медленного чтения файла и перед записью повторно проверяется userId Supabase-сессии. Storage upload, проверка существующей памяти и RPC получают Authorization проверенной сессии в конкретном запросе. Поздняя смена токена глобального клиента не превращает этот запрос в действие другого пользователя. Токен не журналируется и не выводится.
- До чтения первого файла проверяется вся выбранная коллекция: до пяти файлов, поддерживаемый MIME, совместимость типа image/video и известный размер. Известный неподдерживаемый MIME не подменяется по имени файла; расширение используется только при отсутствующем/generic MIME.
- File.size на native и web проверяется до чтения целого файла. Для web URI также учитывается доступный Content-Length. Размер полученного ArrayBuffer остаётся окончательной клиентской проверкой; лимит bucket на сервере не менялся. Байты оригинала не перекодируются.
- Галерея получила синхронную блокировку от двойного тапа. Сохранение невозможно до ответа picker, форма на это время заблокирована. Отмена не стирает выбор; повторный выбор объединяется без дублей до пяти файлов. Устаревший результат сменившегося account/family scope игнорируется.
- Форма показывает подготовку/загрузку конкретного файла, проверку результата и сохранение записи. Это этапы, а не процент передачи байтов. UI-callback best effort: его исключение не запускает откат успешной загрузки. Поздний callback не меняет другой account scope.
- При неизвестном результате RPC сохранены прежние правила: journal до RPC, тот же UUID/содержимое при повторе, проверка результата и отсутствие автоматического удаления отправленных файлов. При смене аккаунта очистка не вызывается заведомо под новым пользователем.

## Оставшиеся границы

- Аварийное завершение до записи journal или отказ пред-RPC очистки могут оставить приватные непривязанные объекты. Durable-журнал загрузки/автоматическая серверная очистка ещё не реализованы; эта работа не выдаёт их за удалённые.
- Очистка Storage не имеет того же per-request header параметра SDK: аккаунт проверяется непосредственно перед ней, серверная RLS остаётся окончательной защитой при смене в полёте.
- Это не побайтовое определение формата и не антивирус/перекодирование. Не все файлы телефонов имеют EXIF; дата видео здесь не извлекается.
- `getPendingResultAsync` для уничтожения Android Activity пока не подключён: нужен scoped-журнал намерения picker, иначе глобальный старый результат можно прикрепить не к той форме. Обычный возврат/отмена проверены локальными обработчиками.
- Перед RPC локальный журнал содержит текст/пути без токенов, но не зашифрован. Не очищать данные приложения при неизвестном результате отправки.
